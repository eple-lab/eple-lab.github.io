OT가 끝나고 드디어 정규 과정 첫 모듈. **바이브 코딩으로 웹 서비스 개발하기**.
7레슨 중 첫 번째는 개발 환경 설정이었다.

> **3줄 요약**
> - 개발 환경은 AI에게 일을 시키고, 그 결과를 바로 **검토·수정하기 위한 작업대**다.
> - "설치했습니다"라는 AI의 말보다 **내 터미널에 찍힌 버전 번호**를 믿는다.
> - 바이브 코딩 루프: **지시 → 생성 → 판단 → 수정 지시**. 이 한 바퀴가 핵심.

## 작업대는 다섯 가지

| 도구 | 하는 일 |
|---|---|
| Claude Code | 자연어로 지시하면 파일을 직접 만들고 고치는 메인 도구 |
| Node.js · npm | Next.js가 돌아가는 실행 엔진과 패키지 매니저(+nvm) |
| uv | 파이썬 도구 관리 (나중에 MCP 쓸 때 필요) |
| Git | 변경 기록. AI가 고친 걸 비교하고 되돌리기 |
| 터미널 | 명령을 넣고 결과를 눈으로 보는 CUI 창 |

수업에서 인상깊었던 AI와 코웤하는 방법

**"버전을 보여줘"라고 덧붙이는 이유** - AI가 "설치했습니다"라고 해도, 그 말만으로는 내 컴퓨터에서 진짜 되는지 모른다.
버전 출력은 AI의 주장을 **내가 검증하는** 제일 쉬운 방법이다.

## 나는 손으로 했다

Claude Code에게 "환경 세팅 다 해줘"라고 맡기는 빠른 길도 있었는데, 나는 CLI로 직접 했다.
**이런 건 내가 기억하고 있어야 한다고 생각해서.**

Agent과정 시작 전에 깔아둔게 많아서 크게 막힌 건 없었다.(걱정많은 성격 ㅋ)
그런데 수업 끝나고 저녁 먹고 다시 보다가... nvm을 안 깔았다는 걸 알았다 ㅋ
그래서 nvm 깔고, 낮은 버전 Node·npm 올리고, 환경 설정(PATH)이 충돌 나서 정리하고, 이미 깔려 있던 uv도 다시 세팅했다.

이 삽질기는 따로 자세히 적어 뒀다.

## 터미널·셸·커널·프롬프트

| 이름 | 역할 |
|---|---|
| 터미널 | 키 입력을 전달하고 결과를 보여 주는 창 |
| 셸 | 명령을 해석하고 프로그램을 실행 (macOS는 zsh, Windows는 PowerShell) |
| 커널 | 프로그램이 CPU·메모리·파일을 쓰게 중개하는 운영체제의 중심 |
| 프롬프트 | "명령 받을 준비 됐어"라는 표시 |

터미널 프로그램이 몇 개 없는 줄 알았는데, 생각보다 종류가 많아서 신기했다.
그래도 나는 윈도우에서는 **cmd파** ㅎ

## AI에게 폴더 정리 맡기기 - dry-run

실습 2는 AI에게 연습 폴더 정리를 맡기는 거였다. 프롬프트 규칙이 좋았다.

- 삭제 명령은 절대 실행하지 마.
- 먼저 **dry-run**(실제로 바꾸지 않고 "무엇을 할지"만 보여 주기)으로 목록부터.
- 내가 **'승인'**이라고 답한 뒤에만 실행해.
- 같은 이름이 있으면 덮어쓰지 말고 멈춰서 물어봐.

나는 이 실습을 AI에게 따로 시키지는 않았다.
Claude Code는 이미 알아서 `ls`·`echo` 등을 쓰고 있었으니까.

## 바이브코딩 첫 주 첫날을 마치고

직접 하는 것과 AI에게 맡기는 것 중 하나가 항상 낫지는 않다.
그래도 **기억해야 할 건 손으로, 반복은 AI에게.** 그리고 어느 쪽이든 이해와 결과 검토는 내 몫.
