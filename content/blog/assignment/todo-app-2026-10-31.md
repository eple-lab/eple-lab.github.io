"백엔드와 데이터베이스 - 데이터가 남는 서비스 만들기" 과제로, 하위 태스크가 있는 Todo 앱을 만들었습니다. 내 컴퓨터의 SQLite(길 A)에서 시작해 Supabase로 저장소를 옮기고(길 B), 선택 과제인 Render 배포(길 C)까지 했습니다.

<!--more-->

## 과제

| 항목 | 내용 |
|---|---|
| 무엇을 | 길 A를 완료한 뒤 길 B로 전환한 Todo 앱 + PRD.md |
| 확인 | 로컬과 Supabase에서 각각 껐다 켜도 할 일이 남는지, 삭제·완료가 동작하는지 |
| 기록 | 클라우드 전환과 RLS 확인 기록 한 줄씩. 배포했다면 접속 URL |

## 만든 앱

큰 할 일(Todo) 아래에 하위 태스크(Task)를 두고 하나씩 체크하는 앱입니다.

| 기능 | 내용 |
|---|---|
| 기본 CRUD | 할 일·태스크 추가, 목록, 완료, 삭제 |
| 하위 태스크 (내가 넣은 기능) | 태스크는 반드시 하나의 할 일에 속한다. 안 끝난 태스크가 있는 할 일을 완료하면 확인 후 함께 완료 |
| 마감일 | 필수, 기본값 오늘, 지난 날짜 금지. "오늘 할 일만 보기" |
| 검색 | 할 일·태스크 제목 |
| 중복 금지 | 미완료 할 일끼리, 같은 할 일 안의 태스크끼리 |
| 자동 정리 | 완료 후 90일 지나면 자동 삭제 |
| 로그인 (길 B) | Supabase Auth 이메일 회원가입·로그인, RLS로 내 할 일만 |

## 길 A → B → C

| | 데이터 | 서버 | 로그인 |
|---|---|---|---|
| 길 A | 내 컴퓨터 SQLite (`data/todo.db`) | 내 컴퓨터 | 없음 |
| 길 B | Supabase (클라우드 Postgres) | 내 컴퓨터 | 이메일, RLS |
| 길 C | Supabase | Render | 이메일, RLS |

길 A 코드는 `path-a` 태그로 남기고, 길 B를 브랜치에서 쌓은 뒤 main에 합쳤습니다. 지금은 `.env`에 Supabase 정보가 없으면 SQLite, 있으면 Supabase로 동작합니다.

## 지킨 원칙

- 화면은 백엔드 API에만 요청하고, Supabase 주소와 키는 서버의 `.env`에만 둔다.
- 서버는 관리자 키 없이, 로그인한 사용자의 토큰으로만 DB를 부른다. 토큰은 httpOnly 쿠키에 둔다.
- DB에 넣는 값은 파라미터화 쿼리로만 처리한다.
- 화면에서 막는 규칙은 백엔드와 DB 제약조건에서도 다시 검사한다.

## DB 구조

표 2개, `todos 1 : N tasks`입니다. Supabase 모드에서는 할 일마다 주인(`user_id`)이 있고, RLS로 자기 행만 다룹니다.

| 표 | 주요 열 |
|---|---|
| todos | id, user_id, title, due_date, completed, completed_at |
| tasks | id, todo_id (NOT NULL, 할 일 삭제 시 함께 삭제), title, completed |

## 확인 기록

| 항목 | 결과 |
|---|---|
| 길 A 로컬 저장 | 할 일 4개·태스크 8개 등록 → 서버를 껐다 켜도 그대로. DB 파일에서도 todos 4행, tasks 8행 확인 |
| 길 B 클라우드 전환 | 저장소 SQLite → Supabase, Supabase Auth 로그인 추가 |
| 길 B 저장 | Render 운영 서버에서 할 일 추가 → 새로고침 후에도 유지. 서버가 쉬었다가 다시 켜진 뒤에도 그대로였고, Supabase Table Editor에서 `todos` 행과 `user_id`도 확인 |
| 길 B RLS | 계정 두 개로 `npm run check:rls` **19/19 통과**. 서버 API와 Supabase 직접 호출 양쪽에서, 다른 계정의 할 일 조회·검색·수정·완료·태스크 추가·삭제가 모두 거절됨. 로그인 안 한 사용자는 표 조회 자체가 거절됨 |
| 기본 기능 자동 테스트 | `npm test` 14가지 (CRUD, 규칙, 재시작 후 유지, 90일 자동 삭제) |
| 길 C 배포 | Render (Free, Supabase 모드). 비로그인 상태에서 API는 401, 화면 파일에 Supabase 키 없음 |
