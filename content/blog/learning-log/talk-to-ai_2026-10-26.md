1. 개발 환경 및 터미널 기본 명령어
터미널의 역할을 이해하고, 파일 시스템을 제어하는 기본 명령어를 실습 위주로 정리해 보세요.

터미널의 개념: GUI(그래픽 화면) 대신 텍스트 명령어로 운영체제와 소통하는 방법.

주요 명령어 정리:

pwd (Print Working Directory): 현재 내가 작업 중인 폴더의 절대 경로 확인

ls (List): 현재 폴더에 있는 파일 및 폴더 목록 출력 (-l, -a 등 옵션도 가볍게 언급)

cd (Change Directory): 원하는 폴더로 이동 (cd ..로 상위 폴더 이동 등)

mkdir (Make Directory): 새로운 폴더 생성

touch: 빈 파일 생성 또는 파일 수정 시간 업데이트

mv (Move): 파일을 다른 위치로 이동시키거나 파일 이름 변경

2. Node.js & npm
자바스크립트의 생태계와 패키지 관리를 이해하는 단계입니다.

Node.js: 웹 브라우저 안에서만 실행되던 자바스크립트를 컴퓨터(운영체제) 환경에서도 실행할 수 있게 해주는 자바스크립트 런타임(Runtime).

npm (Node Package Manager): 전 세계 개발자들이 만든 오픈소스 패키지(라이브러리)를 설치하고 관리해 주는 도구.

## Node.js는 무엇이고 왜 엔진일까

자바스크립트라는 친구를 '인터넷 창(웹 브라우저) 안에서만 놀 수 있는 요리사'라고 생각해보세요. 이 요리사는 원래 웹사이트를 예쁘게 꾸미고 움직이는 일만 할 수 있었어요.

그런데 노드JS(Node.js)는 이 요리사에게 ‘푸드트럭’을 선물해 준 거예요!

푸드트럭이 생기니 요리사가 인터넷 창이라는 가게를 벗어나서, 컴퓨터 안 어디든 돌아다니며 맛있는 요리(프로그램)를 만들 수 있게 되었답니다.

즉, 인터넷 창을 켜지 않고도 내 컴퓨터에서 직접 자바스크립트로 프로그램을 실행하고 만들 수 있게 해주는 마법 같은 엔진이에요!

자동차 엔진: 기름(연료)을 넣으면 에너지를 만들어내서 자동차가 굴러가게 만들어주는 핵심 장치죠? 엔진이 없으면 자동차는 그냥 쇠붙이 덩어리일 뿐이에요.

소프트웨어 엔진 (Node.js): 사람이 쓴 프로그래밍 언어(코드)를 컴퓨터가 알아듣고 실제로 움직이게끔 힘과 에너지를 불어넣어 주는 핵심 부품(실행기)이에요.

즉, Node.js라는 엔진 속에는 자바스크립트를 컴퓨터가 이해할 수 있는 언어로 빠르게 번역하고 실행해 주는 핵심 기술(구글의 V8 엔진 등)이 들어 있어서, 자바스크립트가 컴퓨터 안에서 쌩쌩 돌아갈 수 있게 만들어 주는 거랍니다!

맞아요! 아주 날카로운 지적이에요.

자바스크립트는 원래 웹 브라우저(크롬, 사파리 등) 안에서 그냥 아주 잘 돌아갑니다. 왜냐하면 웹 브라우저 자체가 자바스크립트를 실행해 주는 '실행 환경'을 이미 품고 있기 때문이죠. (크롬에는 V8 엔진이 들어있어요!)

하지만 여기서 중요한 차이가 있습니다:

브라우저 안에서 실행될 때: 웹페이지를 꾸미고, 버튼 클릭을 감지하고, 화면을 움직이는 역할(프론트엔드)을 합니다. 이때는 브라우저가 실행 환경 역할을 해줍니다.

브라우저 밖(내 컴퓨터 터미널이나 서버)에서 실행할 때: 브라우저를 끄고 컴퓨터 자체에서 자바스크립트 파일을 돌리거나, 서버를 만들거나, 컴퓨터의 파일을 직접 읽고 싶을 때는 브라우저가 없기 때문에 컴퓨터가 자바스크립트를 이해하지 못합니다.

즉, "웹 브라우저라는 울타리 밖으로 나와서, 내 컴퓨터(운영체제) 위에서도 자바스크립트가 똑같이 숨 쉬고 돌아갈 수 있게 판을 깔아주는 프로그램"이 바로 Node.js인 거랍니다!

## React, Vue, Vite와 SPA

우리가 자주 쓰는 카카오톡이나 인스타그램 같은 완성된 프로그램이 바로 어플리케이션(앱)이라면, 이 친구들은 다음과 같은 역할을 합니다:

React & Vue: 웹사이트나 앱의 화면(UI)을 쉽고 예쁘게 만들 수 있도록 도와주는 자바스크립트 라이브러리/프레임워크 (건물을 지을 때 쓰는 조립식 철골 구조나 블록 세트 같은 역할!)

Vite: 코드를 작성할 때 화면을 아주 빠르게 띄워주고, 개발이 끝난 코드를 사용자가 쓸 수 있게 깔끔하게 묶어(빌드)주는 개발 및 빌드 도구 (건물을 지을 때 쓰는 고성능 공구 세트!)

즉, 완성된 프로그램이 아니라, 그런 프로그램을 뚝딱뚝딱 만들어내는 마법의 건축 자재와 공구들이라고 생각하시면 됩니다!

React나 Vue 같은 도구들을 활용해서 만드는 대표적인 웹 형태가 바로 SPA(Single Page Application, 단일 페이지 애플리케이션)입니다.

💡 SPA(Single Page Application)란?
전통적인 웹 방식: 페이지를 이동할 때마다 서버에서 새로운 HTML 페이지를 통째로 새로 불러와서 화면이 깜빡임.

SPA 방식: 처음 딱 하나의 HTML 페이지(Single Page)만 받아온 뒤, 사용자가 메뉴를 누르거나 이동할 때 필요한 데이터만 자바스크립트로 쏙쏙 바꿔치기해서 마치 여러 페이지가 있는 것처럼 부드럽고 빠르게 움직이게 만듦.

🔗 오늘 배운 도구들과의 관계
React / Vue: 이 SPA를 아주 쉽고 체계적으로 만들 수 있게 도와주는 대표적인 프론트엔드 도구(라이브러리/프레임워크).

Vite: 그 SPA 프로젝트를 만들고 개발할 때, 코드를 수정하면 화면에 빛의 속도로 반영되도록 도와주는 고성능 빌드 도구.

즉, "React와 Vue는 SPA를 만들기 위한 주력 기술이고, Vite는 그걸 빠르게 도와주는 부스터 역할"이라고 이해하시면 완벽합니다!

개념을 깔끔하게 정리해 드릴게요!

기계어: 컴퓨터의 두뇌(CPU)가 태어날 때부터 이해할 수 있는 0과 1로 이루어진 최종 형태의 언어입니다. 번역 과정이 아예 필요 없어서 속도가 가장 빠르지만, 사람이 읽기엔 너무 어렵습니다.

인터프리터 언어 (예: 파이썬, 자바스크립트): 사람이 읽기 쉬운 언어로 작성된 코드를, 컴퓨터가 실행할 때 한 줄씩 실시간으로 통역(인터프리트)해서 컴퓨터가 알아듣게 바꿔주는 언어입니다.

즉, 인터프리터(또는 컴파일러)가 최종적으로 만들어내는 목적지가 바로 '기계어'라고 생각하시면 아주 정확합니다!

개념을 깔끔하게 정리해 드릴게요!

사람이 ADD 같은 어셈블리어로 코드를 작성합니다.

즉, 어셈블리어는 기계어와 1:1로 맞물려 돌아가는 가장 저수준(Low-level)의 언어이지만, 0과 1 그 자체인 기계어와는 표현 방식(글자 vs 숫자)에서 차이가 있답니다!

기존의 파이썬 패키지 관리자들(pip, poetry, virtualenv 등)은 패키지를 설치하거나 가상환경을 만들 때 시간이 꽤 걸렸습니다. 하지만 uv는 Rust로 만들어져서 기존 도구들보다 수십 배에서 수백 배 이상 번개 같이 빠릅니다. (체감이 확 될 정도예요!)

믿을 수 있는 제작사

파이썬 초고속 코드 검사기(Linter)인 Ruff를 만들어 업계를 뒤집어놓았던 Astral이라는 회사에서 만들었기 때문에, 출시되자마자 전 세계 개발자들의 엄청난 신뢰와 호응을 받았습니다.

기존 파이썬 개발의 가장 큰 불만 중 하나가 "환경 세팅과 패키지 설치가 느리다"는 점이었는데, uv가 등장하면서 이 문제가 단숨에 해결되어 지금은 거의 필수 도구처럼 자리 잡고 있답니다! 노션에 아주 핵심을 잘 정리해 두셨네요. 👏

🥊 콘다(Conda) vs uv 한눈에 비교
콘다 (Conda / Anaconda / Miniconda)

특징: 데이터 과학이나 머신러닝 분야에서 표준처럼 쓰이는 거대한 패키지 & 환경 관리자입니다.

장점: 파이썬뿐만 아니라 C언어 기반의 무거운 과학 계산용 라이브러리(NumPy, Pandas, 딥러닝 라이브러리 등)까지 알아서 척척 세트로 묶어서 관리해 줍니다.

아쉬운 점: 편리하지만, 필요한 패키지들의 관계를 복잡하게 계산하다 보니 설치 속도가 다소 느리다는 평이 많습니다.

uv

특징: 앞서 노션에 적어두신 것처럼 파이썬 생태계의 패키지 관리(pip, virtualenv 등)를 초고속으로 대체하기 위해 나온 차세대 올인원 도구입니다.

장점: 시스템에 파이썬 버전을 설치하는 것부터 가상환경 생성, 패키지 설치까지 말도 안 되게 빠릅니다. (Rust 언어로 만들어져서 기존 파이썬 도구들과는 속도 차이가 극심해요.)

차이점: 콘다처럼 데이터 과학 전용의 무거운 바이너리 패키지 생태계를 통째로 관리하기보다는, 일반적인 파이썬 웹 개발이나 스크립트 환경에서 번개 같은 속도로 가상환경과 패키지를 다루는 데 특화되어 있습니다.

결국 똑같은 파이썬 인터프리터가 코드를 읽어서 실행하는 것이기 때문이에요.

루비가 만들어진 가장 큰 목적은 컴퓨터가 일을 빨리 처리하게 하는 게 아니라, 사람(개발자)이 코드를 쓰면서 스트레스를 받지 않고 즐거움을 느끼게 하는 것이었습니다. 코드가 마치 영어 문장처럼 아주 우아하고 직관적으로 읽히는 게 특징이에요.

순수한 객체지향 언어

자바스크립트나 파이썬 등은 객체지향 문법을 섞어서 쓰지만, 루비는 숫자 하나, 글자 하나조차도 전부 '객체'로 취급할 정도로 철저하게 객체지향적입니다.

인터프리터 언어

자바스크립트나 파이썬처럼 코드를 한 줄씩 읽어가며 실행하는 인터프리터 방식입니다.

🚄 세상에 대폭발을 일으킨 주역: 루비 온 레일즈 (Ruby on Rails)
